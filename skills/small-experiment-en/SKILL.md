# Two-week small experiment

If you set the bar after seeing results, you will read them in your favor. So write the bar down before you start. This skill is a template for that. It does not promise any outcome.

## Starting: decide these 7 items first
Fill each in. If one is missing, ask the user. Never fill in by guessing.

1. **Hypothesis**: one sentence: "If I do X, Y will go up (or down)."
2. **Evidence**: why you think so (real numbers, reader comments, competitor observations). If weak, say honestly: "Evidence is weak, but worth trying."
3. **Metric**: one number you can check on a screen (views per post, click-through rate, inquiries). Do not pick a number you cannot get.
4. **Baseline**: the same number before the test, and how it was taken (for example, the average of the last 2 to 4 weeks). If unavailable, write "not measured"; then getting the baseline is the first experiment.
5. **Judging date**: a date within 2 weeks of the start.
6. **Keep rule**: in numbers, for example "at least X% above baseline, or at least N results".
7. **Stop rule**: in numbers, for example "no change from baseline, or below X%". Also write one candidate for the next move if you stop or change.

### Design tips
- Change only one thing. If you change several, you cannot tell what worked.
- With small counts, differences often fall within chance. Write the minimum count needed when you set the rules.
- If the test involves money, publishing, sending, or platform rules, get the owner's confirmation before starting.
- Never change the baseline or period afterward to make numbers look better.

## Record format
One experiment = one block. A spreadsheet or a note is fine.

```
Experiment ID: 2026-xx-xx-short-name
Hypothesis:
Evidence:
Metric:
Baseline (current number, how taken):
Start date / Judging date:
Keep rule:
Stop rule:
Next-move candidate:
Progress notes (date, number, screen checked):
Decision: (keep / change / stop)
Reason (with numbers):
Next move:
```

## During the test
- Record the metric once a week. Write only numbers you checked on a screen. If you could not get it, write "not measured (reason)". "Not measured" and "measured zero" are different things.
- Do not change the rules midway. If you want to, register a new experiment.

## Judging (on the judging date)
1. Compare the recorded numbers with the keep rule and stop rule.
2. If counts are small and the difference is slight, write "may be within chance". You may extend once, with a new judging date and new rules.
3. Choose one, and give the numbers as the reason:
   - **Keep**: the keep rule was met. Next, design a test that scales it up or adds another factor.
   - **Change**: it did not work. Write a hypothesis for why, and the replacement move.
   - **Stop**: the stop rule was hit. Always name one replacement move.
4. Whatever the decision, never leave "next move" empty. Do not just stop and end there.

## Never
- Fill in numbers by guessing.
- Promise results ("this will definitely grow").
- Change the bar after seeing results.
