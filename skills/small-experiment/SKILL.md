# 2週間の小さな試し

結果を見てから基準を決めると、都合よく解釈してしまう。だから、始める前に基準を書く。このスキルはそのための型。成果を約束するものではない。

## 始める：先に決める7項目
次を埋める。埋まらない項目は聞き返す。推測で埋めない。

1. **仮説**：「何をすると、何が増える（減る）と考えるか」を1文で
2. **根拠**：その仮説を思いついた理由。実際の数字・読者の声・競合の観察など。根拠が弱いときは「根拠は弱いが試す価値がある」と正直に書く
3. **測る数字**：画面で確かめられる1つ（例：投稿あたりの閲覧数、クリック率、問い合わせ件数）。取れない数字は選ばない
4. **今の数字（基準）**：試す前の同じ数字。直近の2〜4週間の平均など、取り方も書く。取れなければ「未取得」とし、まず基準を取るのが最初の試しになる
5. **判定日**：開始から2週間以内の日付
6. **続ける目安**：「基準より◯％以上、または◯件以上」のように、数字で
7. **やめる目安**：「基準と変わらない、または◯％未満」のように、数字で。やめる・替えるときの次の手の候補も1つ書いておく

### 設計のコツ
- 変えるのは1つだけ。複数変えると、何が効いたか分からない。
- 件数が少ないと、差は偶然の範囲に入りやすい。目安を決めるとき、必要な最小の件数も書く。
- お金・公開・送信・規約に関わる試しは、始める前に自分（本人）の確認を取る。
- 数字を良く見せるために、基準や期間を後から変えない。

## 記録の形
1試し＝1ブロック。表計算でもメモでもよい。

```
試しID：2026-xx-xx-短い名前
仮説：
根拠：
測る数字：
基準（今の数字・取り方）：
開始日／判定日：
続ける目安：
やめる目安：
次の手の候補：
経過メモ（日付・数字・見た画面）：
判定：（続ける／替える／やめる）
判定の理由（数字）：
次の手：
```

## 途中経過
- 週に1回、測る数字を記録する。画面で確かめた数字だけ書き、取れなければ「未取得（理由）」と書く。「未取得」と「0」は別物。
- 途中で目安を変えない。変えたくなったら、新しい試しとして登録し直す。

## 判定する（判定日）
1. 記録した数字を、続ける目安・やめる目安に当てはめる。
2. 件数が少なく差が小さいときは「偶然の範囲かもしれない」と書き、延長する場合は1回だけ、新しい判定日と目安を決める。
3. 次のどれかにして、理由に数字を書く。
   - **続ける**：目安を超えた。次は規模を広げる試しか、別の要素を足す試しを設計する。
   - **替える**：効かなかった。効かなかった理由の仮説と、替える次の手を書く。
   - **やめる**：やめる目安に当たった。代わりの手を必ず1つ書く。
4. どの判定でも「次の手」を空にしない。やめて終わりにしない。

## 禁止
- 数字を推測で埋める。
- 「必ず伸びる」など、結果の約束をする。
- 結果を見てから基準を変える。
